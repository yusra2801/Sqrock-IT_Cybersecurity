### Day 18 — SQL Injection (SQLi) Log Detection Engine

SQL Injection tab hoti hai jab attacker apne malicious SQL commands ko normal user input ke through inject kar de, jaise `' OR '1'='1` (login bypass ke liye) ya `UNION SELECT` (extra data nikalne ke liye). Defenders in patterns ko access logs mein regex ke zariye detect karte hain — meta-characters jaise single quotes, `--`, `#`, ya keywords jaise `UNION SELECT` search kar ke. Is task mein maine 3 mock log entries analyze kiye: pehli normal request thi (koi threat nahi), doosri mein login bypass attempt (`' OR '1'='1`) thi, aur teesri mein UNION-based data extraction attempt thi. Script ne successfully dono malicious entries detect kar ke unki source IP aur pattern flag ki, jabke normal request ko ignore kar diya.

**Unparameterized queries vs Prepared Statements:**
Unparameterized query mein user input directly SQL string ke andar concatenate ho jata hai, jaise: `f"SELECT * FROM users WHERE id={user_input}"`. Agar `user_input` mein attacker `' OR '1'='1` daal de to query ka structure hi badal jata hai aur attacker unauthorized data access kar sakta hai. Prepared Statements mein query ka structure pehle hi fix (compile) ho jata hai aur user input sirf ek "value" ki tarah treat hota hai, kabhi bhi command ki tarah execute nahi hota — chahe attacker jo bhi input de, wo sirf data samjha jata hai, code nahi.
